01

Component & UI Architecture

앱과 웹에서 함께 사용하는 UI는 공통 컴포넌트로 구성하고, 환경에 따라 달라지는 화면 구조는 분리했습니다.

과제 — 공통 UI와 환경별 차이의 공존

Highs Pro App과 Highs App/Web을 구축하면서 반복되는 UI의 일관성을 유지해야 했습니다. 동시에 앱과 웹은 레이아웃과 화면 이동 구조가 달라, 모든 화면을 하나의 구조로 처리하기보다 공통으로 사용할 부분과 따로 구성할 부분을 구분할 필요가 있었습니다.

설계 — 재사용할 영역과 분리할 영역 구분

반복되는 UI는 React 기반의 공통 컴포넌트로 구성했습니다. 화면의 바탕이 되는 Layout과 Route는 App/Web 환경에 맞게 분리해, 공통 UI를 각 환경의 화면 안에서 사용할 수 있도록 했습니다.

구현 — 구조와 스타일의 역할 분리

  • Layout / Route: 앱과 웹의 화면 구성 및 이동 구조를 환경별로 분리했습니다.
  • Style: 함께 사용하는 스타일과 환경별로 달라지는 스타일을 나누었습니다.
  • Component: 여러 화면에 반복되는 UI를 공통 컴포넌트로 만들어 재사용했습니다.

결과 — 일관성을 유지하면서 변경에 대응

공통 UI의 일관성을 유지하면서 환경별 UI 변경에 대응할 수 있는 구조를 구성했습니다. 공통으로 적용할 변경과 특정 환경에만 적용할 변경을 구분하는 것이 설계의 핵심이었습니다.

02

Adaptive UI

같은 서비스라도 사용자 권한, 화면 크기, 글씨 크기 설정에 따라 필요한 UI가 달라집니다. 이 세 가지 조건을 고려해 화면을 구현했습니다.

사용자 권한 — 이용 범위에 맞는 UI

사용자 권한에 따라 화면에서 제공해야 하는 UI가 달라지는 점을 고려했습니다. 공통으로 사용하는 UI를 바탕으로 권한별 차이를 반영해, 사용자의 이용 범위에 맞는 화면을 구성했습니다.

화면 크기 — 모바일부터 데스크톱까지

모바일과 데스크톱처럼 서로 다른 화면 크기에서 사용할 수 있도록 반응형 UI를 구현했습니다. 화면 너비에 따라 달라지는 공간을 고려해, 각 환경에 맞게 콘텐츠를 보여주는 데 중점을 두었습니다.

큰 글씨 모드 — 글씨 크기에 따른 화면 대응

기본 글씨 크기뿐 아니라 큰 글씨 모드에서도 사용할 수 있도록 UI를 구성했습니다. 글씨가 커지면 같은 내용이 차지하는 공간도 달라지므로, 화면 크기와 함께 글씨 크기 설정을 UI 대응 조건으로 다루었습니다.
